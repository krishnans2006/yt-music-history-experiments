# My Activity extractor

Open your logged-in [YouTube History page](https://myactivity.google.com/product/youtube), with the English interface and the intended Google account selected. Remove keyword filters if you want the whole history. Paste all of [myactivity-extract.js](myactivity-extract.js) into DevTools → Console. Click **Start / Resume** in the added panel and keep the original tab and collection window open.

The default range is the known Radioactive interval, **December 7, 2024 04:00–04:40 UTC** (December 6, 22:00–22:40 Chicago time). Start there. Before processing any new range, the extractor checks the known Renegades occurrence and two adjacent seconds to test one-second filtering. A failed calibration stops the run and saves the evidence; it does not silently proceed with rounded boundaries. No authenticated run of this extractor has been performed by the coding agent.

**Access and pacing.** There is no published safe automation quota established for this My Activity interface. The script uses a delay between actions, not session or daily action caps:

- One collection window, one run at a time, enforced across tabs with Web Locks.
- At least **10 seconds between navigation, pagination scrolls, and robots checks**. A longer applicable `Crawl-delay` is honored. Page loading and settling may make the actual interval longer.
- Collection continues until the range is finished, you pause it, or an error/restriction occurs. The delay is set in `LIMITS` at the top of the script. Existing checkpoints can resume with this pacing; previous action counts do not stop them.
- No automatic retries. Detected traffic warnings or HTTP 429/503 stop the run with at least a 24-hour cooldown. An available `Retry-After` on the robots response can extend it. Sign-in, verification, access errors, parser failures and timeouts stop collection too.
- The script checks the host's `robots.txt` before querying history. It stops if the file is unavailable, unrecognized or disallows the target path. There is no bypass switch. Checking robots rules is not a grant of permission under every applicable term.

One browser navigation can itself make several Google requests; the script limits its own page actions, not every internal browser request. Response status visibility also depends on browser support, so detection includes visible page warnings. Do not run the older probe collector or other history scrapers concurrently. There is no proxy rotation, identity spoofing, CAPTCHA solving, credential export or history mutation. No song/watch link, delete control or history-setting control is clicked.

Google's [terms](https://policies.google.com/terms?hl=en&gl=us) prohibit bypassing protective measures and automated access contrary to machine-readable restrictions. [YouTube's terms](https://www.youtube.com/static?template=terms) separately restrict automated access to its service. This implementation targets the Google My Activity interface, not YouTube playback/InnerTube, and does not establish an exemption from applicable terms. I could not retrieve My Activity's current robots file from the coding environment; the script checks it in the browser and fails closed. If it disallows collection, use the supported data-access/export routes described in [the research](recovery-next-steps.md). Neither slow pacing nor ownership of the account guarantees permission or that an account will never be flagged.

**What it recovers.** Each query uses an explicit half-open UTC interval. A complete empty/non-Music result finishes that interval. A result with Music activity is split in two, retaining both halves, until nonempty intervals are at most one second wide. The split uses observed minute boundaries where possible, reducing empty searches around sparse activity, then uses binary subdivision within a minute. Truncated pages are split too, rather than being treated as empty. This avoids assuming that the oldest row in a broad daily summary is a safe cursor and avoids skipping other occurrences within a displayed minute.

Only cards explicitly labelled **YouTube Music** enter the exported `events` list. Ordinary YouTube rows are used to validate bounds but are excluded from that list. Multiple title/duration links on one card do not become multiple events. Raw page snapshots are preserved in `queries`, so they can contain ordinary YouTube rows. Broad-query Music observations remain in those query records; they are not counted again as resolved events.

The output keeps `timeIntervalUTC` rather than inventing exact seconds from minute-rounded display text. The browser's local timezone is saved and checked on resume, with both candidate offsets retained for ambiguous daylight-saving clock minutes. Same-video activity in different leaf intervals stays separate. Multiple plays within a single leaf may still be consolidated, and activity is not proof of a completed play or repeat-one mode. `coverage.partitionComplete` means all queued intervals were examined to the configured resolution; `physicalPlayCompleteness` remains unknown.

**Pause, resume and download.** Each completed query and its pending child intervals commit together to a dedicated IndexedDB database on the My Activity origin. **Pause** stops further actions and leaves unfinished work pending. Reloading the page and pasting the script again restores the most recent run; the selector lists other saved ranges. Use the same browser profile, account, filters and timezone. If you changed the default Google account without changing its URL, the script cannot reliably detect that account switch.

The script downloads `myactivity-extract-<run-id>.json` when it pauses or finishes. **Download JSON** also saves the current checkpoint while running. Keep a copy under `media/`; it contains the UTC range, pending work, raw query evidence, resolved Music observations, and the latest action time/any throttle cooldown. `unresolvedObservations` preserves Music observations not yet matched to leaf results, including observations waiting on pending queries. Restore an exported checkpoint with the file input, then click **Start / Resume**. Importing does not erase a newer local checkpoint, the latest action time, or a throttle cooldown. Older checkpoints with action-count history are also supported. An interrupted query may be repeated on manual resume, but already committed work is not repeated. Error recovery requires a manual resume.

After reviewing a successful pilot, edit the UTC range fields to create a new saved run. For the supplied archive, a possible range is `2023-08-25T00:00:00Z` through `2026-11-08T00:00:00Z`. Earlier account history may exist, so this is not a claim about the account's absolute start date. Broad ranges and second-level subdivision can require many queries. Full-history runtime still depends on the number of retained observations and pagination, so faster pacing does not establish a guaranteed completion time.

**Offline checks.** Run `node random/myactivity-extract.test.cjs` and `node random/myactivity-extract.simulation.test.cjs`. Tests cover actual pilot snapshots, duplicate watch anchors, Music-only selection, ignored bounds, DST ambiguity, rules parsing, pacing, and a simulated consolidated history containing repeated activity within one minute. The browser simulation also checks uninterrupted extraction, checkpointing, legacy imports, cross-tab locking, robots denial, HTTP 429, and manual pause/resume. These do not certify Google's live DOM, permission to automate, or complete historical playback retention.
